해결하려던 문제

무기와 판도라 조합이 바뀔 때마다 입력, 능력 부여, 비용, 쿨다운을 개별적으로 처리하면 같은 규칙이 여러 곳에 흩어집니다. 능력의 공통 실행 규칙과 스킬별 데이터를 분리할 필요가 있었습니다.

입력부터 화면까지

  1. Input Tag입력 시작·종료를 ASC에 전달
  2. Ability부여된 능력과 스킬 컨텍스트로 실행
  3. Effect / Attribute비용·쿨다운·속성 변경 처리
  4. ViewModel / HUD속성 변경 알림을 화면에 반영

ASC의 소유와 입력을 분리

PlayerState가 Ability System Component를 소유합니다. ControllerInputComponent는 입력을 Gameplay Tag로 전달하며, 입력 처리 코드가 개별 스킬 클래스에 직접 의존하지 않도록 구성했습니다.

실행할 스킬의 출처를 보존

PandoraSkillBinder는 정의 데이터, 스킬 슬롯과 레벨, 로드아웃 방향을 Runtime Context에 담아 Ability Spec의 SourceObject로 연결합니다. 중복 부여를 확인하고, 실행 중인 능력의 컨텍스트는 갱신하지 않아 진행 중인 시전의 출처를 유지합니다.

서버에서 시작하는 능력 실행

기본 PdGameplayAbility의 네트워크 실행 정책은 ServerInitiated입니다. 능력 부여에는 서버 권한 검사를 두고, 자원·이동·연출 처리는 각각의 런타임 객체로 분리했습니다.

설계의 결과

스킬 정의와 런타임 컨텍스트를 바꿔 전투 구성을 확장하고, 입력·능력·속성·UI의 책임을 나누어 수정 범위를 명확히 했습니다.
