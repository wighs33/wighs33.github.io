해결하려던 문제

전투·UI·스킬 초기화가 서로를 직접 호출하면 로딩 순서와 해제 시점이 얽히기 쉽습니다. 필요한 콘텐츠의 선언, 비동기 로딩, 기능 적용과 게임 시작 판단을 구분해야 했습니다.

기능 초기화 흐름

  1. Experience사용할 콘텐츠와 기능 정의
  2. Manager에셋·Game Feature 비동기 로드
  3. Actions능력·속성·입력·위젯 구성
  4. Gameplay각 시스템의 런타임 실행

설정은 정의 데이터에, 동작은 구성 요소에

ExperienceDefinition과 PandoraDefinition 같은 Data Asset에 구성을 두고, 실행은 Manager·Binder·Component에 맡깁니다. 정의를 참조하는 경로를 명확히 하여 새로운 콘텐츠가 공통 실행 규칙을 재사용하도록 했습니다.

로딩 상태와 실패를 명시

ExperienceManagerComponent는 Unloaded, Loading, LoadingGameFeatures, Loaded, Failed, Deactivating 상태를 구분합니다. 로드 완료와 실패 이벤트를 제공하고, 비활성화 시 런타임 리소스를 정리합니다.

준비 완료와 경기 시작의 경계

Experience의 Loaded는 해당 월드의 에셋과 기능이 준비되었다는 의미입니다. 모든 클라이언트의 입장 완료를 뜻하지 않으며, 경기 시작과 실패 후 대응 정책은 GameMode 등 호출자가 결정하도록 책임을 나눴습니다.

설계의 결과

콘텐츠 로딩과 기능 구성을 공통 흐름으로 정리하고, 각 시스템의 준비·실행·해제 경계를 코드에서 확인할 수 있도록 만들었습니다.
